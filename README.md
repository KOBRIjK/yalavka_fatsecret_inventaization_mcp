# Eda: домашние запасы, FatSecret и Яндекс Лавка

Eda объединяет три MCP-сервиса: учёт продуктов дома, дневник питания FatSecret и покупки в Яндекс Лавке. MCP позволяет помощнику обращаться к этим сервисам из чата. Данные общие для всех чатов, подключённых к одному стеку.

Все рабочие сервисы запускаются через корневой [compose.yaml](compose.yaml). Остатки, журнал операций и настройки подключений хранятся в PostgreSQL. Фоновой синхронизации между сервисами нет: помощник выполняет действия по запросу пользователя.

## Сервисы и адреса

| Сервис Compose | Назначение | Локальный MCP URL |
| --- | --- | --- |
| `pantry` | Остатки по партиям, поступления, списания и история | `http://127.0.0.1:8002/mcp` |
| `fatsecret` | Поиск продуктов и порций, чтение и изменение дневника | `http://127.0.0.1:8001/mcp` |
| `lavka` | Каталог, корзина, предварительный расчёт и оформление заказа | `http://127.0.0.1:8000/mcp` |
| `postgres` | PostgreSQL 17, общее постоянное хранилище | Доступен только внутри сети Compose |

MCP-порты опубликованы только на `127.0.0.1`. Текущий стек предназначен для локального использования владельцем аккаунтов. Публикация этих портов в интернете требует отдельной настройки защиты доступа.

## Требования и первый запуск

Нужны Docker Desktop с поддержкой Linux-контейнеров и Docker Compose с командой `up --wait`. Для внешних сервисов нужны собственные аккаунты: FatSecret с OAuth 1.0 / доступом к Profile API и авторизованная сессия Яндекс Лавки. Локальный Python и `.venv` для запуска стека не нужны.

Все команды ниже выполняются в PowerShell из корня проекта.

1. Запустите Docker Desktop.
2. При первой установке создайте локальный файл окружения, сохранив существующий, если он уже есть:

   ```powershell
   if (-not (Test-Path -LiteralPath .env)) {
       Copy-Item -LiteralPath .env.example -Destination .env
   }
   ```

3. Откройте `.env` локальным редактором и задайте собственный `POSTGRES_PASSWORD`. Не отправляйте содержимое файла в чат и не добавляйте его в Git. Для уже созданной базы сохраняйте действующий пароль: изменение переменной не меняет пароль роли внутри PostgreSQL.
4. Соберите и запустите стек:

   ```powershell
   docker compose up -d --build --wait
   docker compose ps
   ```

При старте `pantry` создаёт недостающие таблицы, затем запускаются FatSecret и Лавка. Отдельный контейнер миграции не нужен. При существующем Docker volume стек использует сохранённые данные; при новой базе запасы и настройки подключений изначально пусты. Настройка внешних аккаунтов описана ниже.

Проверка готовности контейнера MCP проверяет доступность его TCP-порта. Статус `healthy` сам по себе не подтверждает авторизацию во внешнем сервисе.

## Подключение помощника и проверка

В MCP-клиенте добавьте три отдельных подключения с транспортом Streamable HTTP и URL из таблицы выше. Если клиент требует, перезапустите его после изменения подключений.

Для первой проверки достаточно чтения:

- `pantry_status` — доступно ли хранилище и нужна ли начальная инвентаризация;
- `list_stock` — текущие партии продуктов;
- `lavka_status` — заданы ли сессия и местоположение Лавки;
- `get_diary` с конкретной датой `YYYY-MM-DD` — доступен ли дневник FatSecret после авторизации.

Пустая база запасов означает, что инвентаризация ещё не выполнена. Наличие нескольких записей тоже не означает, что перечислены все продукты дома.

## Настройки аккаунтов и перенос старых данных

В рабочем стеке конфигурация Лавки, ключи и OAuth-токен FatSecret читаются из PostgreSQL. Старые локальные `config.json`, `.tokens.json` и файлы окружения коннекторов автоматически не загружаются. Изменения адреса и выбранного способа оплаты Лавки сохраняются в той же базе.

Для явного первоначального импорта предусмотрен [pantry-mcp/migrate.py](pantry-mcp/migrate.py). Скрипту нужен существующий каталог, указанный в `LEGACY_DIR` внутри контейнера. Подготовьте отдельный защищённый каталог с нужными файлами:

| Имя файла в каталоге импорта | Что переносится |
| --- | --- |
| `lavka.json` | Конфигурация Лавки с сессией, местоположением и контекстом доставки |
| `fatsecret.env` | `FATSECRET_CONSUMER_KEY` и `FATSECRET_CONSUMER_SECRET` |
| `fatsecret-token.json` | Ранее полученный OAuth-токен FatSecret |
| `pantry.sqlite3` | Старые таблицы `stock`, `operations` и `events` |

Используйте только файлы, которые нужно перенести. Для новой установки без старого учёта `pantry.sqlite3` не нужен. Если OAuth-токена FatSecret ещё нет, сначала импортируйте ключи, затем пройдите авторизацию командой ниже. Сессия Лавки должна быть получена из собственного авторизованного браузера; автоматического входа в аккаунт нет.

Перед импортом в существующую установку сделайте полную резервную копию и остановите MCP-сервисы. PostgreSQL должен оставаться запущенным:

```powershell
docker compose run --rm backup
docker compose stop pantry fatsecret lavka
$legacyPath = (Resolve-Path -LiteralPath 'C:\private\eda-legacy').Path
docker compose run --rm --no-deps --volume "${legacyPath}:/legacy:ro" --env LEGACY_DIR=/legacy pantry python /app/pantry/migrate.py
docker compose up -d --wait pantry fatsecret lavka
```

Замените `C:\private\eda-legacy` своим каталогом. Проверьте успешное завершение импорта перед запуском MCP. Исходные файлы подключаются только для чтения. Существующие ключи состояния не перезаписываются; автоматическое объединение SQLite с непустым учётом PostgreSQL запрещено. Повторный импорт неизменённой SQLite безопасен, а изменение источника после переноса требует ручной сверки.

Если ключи FatSecret уже импортированы, а токен отсутствует, выполните интерактивную авторизацию в своём терминале:

```powershell
docker compose run --rm --no-deps fatsecret fatsecret-authorize
```

Откройте показанную ссылку самостоятельно, разрешите доступ нужному аккаунту и введите проверочный код в терминале. Токен сохранится в PostgreSQL. Уже сохранённый токен команда не заменяет. Не публикуйте вывод авторизации. Если сессия Лавки истекла или FatSecret требует переподключения, это отдельное обновление сохранённого состояния: повторный импорт не заменяет существующую конфигурацию.

Чтобы обновить только cookies своей сессии Лавки, подготовьте вне проекта закрытый JSON-файл с парами «имя: значение». Из корня проекта при работающем PostgreSQL:

```powershell
docker compose build lavka
$cookieFile = (Resolve-Path -LiteralPath 'C:\private\lavka-cookies.json').Path
docker compose run --rm --no-deps --volume "${cookieFile}:/run/import.json:ro" lavka python /sources/lavka/scripts/import_cookies.py --json /run/import.json
```

Импорт добавляет или заменяет переданные cookies в PostgreSQL. Без параметров местоположения сохранённый адрес не меняется. В выводе видны только количество и признаки наличия сессии и адреса; действительность сессии у Яндекса скрипт не проверяет.

`solve_captcha.py --help` доступен без Playwright. Интерактивный режим рассчитан на компьютер с графическим Chrome и Playwright, а не на серверный контейнер. Для результата требуется `--output` с именем **нового** файла в закрытом каталоге вне проекта; существующий файл скрипт не заменяет и значение в консоль не выводит.

## Основные сценарии и ограничения

Примеры запросов помощнику:

- «Покажи продукты дома и ближайшие сроки годности».
- «Получил 6 яиц, добавь в домашние запасы».
- «Покажи дневник FatSecret за 2026-11-14».
- «Найди этот творог в FatSecret и покажи порции».
- «Собери корзину в Лавке и покажи итоговую стоимость».

Домашние запасы учитываются партиями. `receive_stock` записывает поступления, `change_stock` — списания и исправления, `stock_history` — историю. Неизвестное количество хранится как `null`. Массу упаковки, сроки годности и пересчёт между граммами, штуками и упаковками нельзя угадывать.

Один полученный заказ Лавки заносится целиком с ключом `lavka:order:<id>`, только после получения покупки. Повтор операции с тем же `operation_key` и теми же данными не дублирует её. Другие данные с тем же ключом отклоняются. Абсолютное исправление остатка через `set` требует актуальной `expected_revision` из `list_stock`.

В FatSecret сначала выбираются конкретный продукт и его порция. `number_of_units` измеряется в единицах выбранной порции API; дату нужно задавать явно в часовом поясе пользователя. Запись или удаление выполняются только по запросу пользователя, без автоматического повтора. При неопределённом результате сначала перечитайте дневник.

Лавка использует общий серверный экземпляр корзины аккаунта: параллельные изменения из приложения или другого клиента могут повлиять на заказ. Оформление состоит из `checkout_preview`, показа состава, адреса, оплаты и итоговой суммы пользователю, затем явного подтверждения оплаты и `confirm_order` с подтверждённой суммой. Изменение корзины требует нового предварительного расчёта. Интеграция Лавки неофициальная; её внешний API может измениться.

## Управление стеком

```powershell
# Проверить контейнеры.
docker compose ps

# Посмотреть последние сообщения локально; перед передачей проверьте их на секреты.
docker compose logs --tail 50 pantry fatsecret lavka

# Остановить сервисы с сохранением контейнеров и данных.
docker compose stop

# Запустить после остановки или применить изменения кода/настроек.
docker compose up -d --build --wait
```

Политика `restart: unless-stopped` возобновляет работу сервисов после перезапуска Docker, если они не были явно остановлены. Не запускайте параллельно старые Python-серверы, отдельные Compose-стеки или второй учёт запасов на SQLite.

## Данные и резервные копии

| Хранилище | Содержимое |
| --- | --- |
| Docker volume `eda_postgres_data` | Запасы, операции, история и секреты подключений |
| Docker volume `eda_pantry_backups` | JSON-копии учёта от MCP-инструмента `backup_pantry` |
| Каталог `backups/` | Полные копии PostgreSQL от сервиса `backup` |
| Корневой `.env` | Локальный пароль PostgreSQL и при необходимости дополнительные переменные Compose |

`backup_pantry` сохраняет только запасы, операции и историю. Для полной копии вместе с конфигурацией подключений выполните:

```powershell
docker compose run --rm backup
```

Копия появится в `backups/eda-....dump` в формате `pg_dump -Fc`. Храните её как секрет: она содержит доступы к внешним аккаунтам. Автоматическое расписание резервного копирования в Compose не задано.

### Восстановление полной копии

Восстановление ниже **заменяет текущие данные** содержимым выбранной копии. Выполняйте его только при намеренном восстановлении, предварительно создав новую копию текущего состояния. Это не команда обычного запуска или миграции.

```powershell
docker compose run --rm backup
docker compose stop pantry fatsecret lavka
docker compose run --rm --entrypoint pg_restore backup --host postgres --username eda --dbname eda --clean --if-exists --exit-on-error /backups/ИМЯ_КОПИИ.dump
# Продолжайте только после успешного завершения pg_restore.
docker compose up -d --wait pantry fatsecret lavka
```

Замените `ИМЯ_КОПИИ.dump` нужным именем файла из `backups/`. Не удаляйте Docker volumes. В частности, `docker compose down -v` удаляет постоянные тома, включая базу и JSON-копии запасов.

После изменений хранения данных или коннекторов обязательны:

```powershell
docker compose build tests
docker compose run --rm tests
```

Проверки используют изолированные схемы PostgreSQL, временные файлы и имитацию внешних записей. Покрываются атомарность, конкурентные списания, защита от повторов, версии остатков, перенос данных и настройки подключений. HTTP-проверки работающих MCP ограничены чтением статуса и списка инструментов. Тесты не должны оформлять реальные заказы или менять настоящий дневник.

Корневой Compose использует только `docker/Dockerfile` и `docker/requirements.txt`. Отдельные Dockerfile, `.venv` и инструкции самостоятельного запуска в каталогах коннекторов не относятся к запуску этого стека.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Compose не запускается | Docker Desktop работает; `.env` существует; `POSTGRES_PASSWORD` задан |
| PostgreSQL отказывает в доступе после правки `.env` | Верните действующий пароль существующей базы; не удаляйте volume для обхода ошибки |
| Порт уже занят | Остановите старый процесс или второй стек, использующий 8000, 8001 или 8002 |
| Контейнер `healthy`, но FatSecret недоступен | Импортированы ли ключи и токен, действуют ли разрешения аккаунта |
| Лавка сообщает об отсутствии сессии или адреса | Проверьте `lavka_status` и сохранённую конфигурацию PostgreSQL |
| Лавка требует CAPTCHA | Это отдельная проверка Яндекса; при необходимости Compose передаёт локальную переменную `YANDEX_LAVKA_MCP_SPRAVKA` |
| Ошибка версии партии или корзины | Перечитайте актуальные данные; для оплаты заново получите предварительный расчёт |
| Ответ записи FatSecret потерян | Перечитайте дневник за ту же дату до решения о повторной записи |
| В запасах нет ожидаемых покупок | Фонового импорта нет; поступления учитываются по запросу после получения |

Для диагностики используйте `docker compose ps` и локальные логи. Не публикуйте `.env`, cookies, токены, строки подключения, дампы и неочищенные логи. Команда `docker compose config` без ограничений вывода может раскрыть подставленные секреты.
